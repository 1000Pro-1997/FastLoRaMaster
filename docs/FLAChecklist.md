# FLA Lora Checklist

**체크한 항목만 모아 프롬프트를 만드는** 노드입니다.
항목마다 로라를 달아둘 수 있어서, 항목을 켜면 프롬프트와 로라가 함께 들어갑니다.

- 클래스: `FLAChecklist`
- 표시 이름: `FLA Lora Checklist` (한국어: FLA 로라 체크리스트)
- 카테고리: `FLA`
- 구현: [`nodes_checklist.py`](../nodes_checklist.py), [`checklist.py`](../checklist.py), [`web/fla_checklist.js`](../web/fla_checklist.js)

[FLALoraTheme](FLALoraTheme.md) 과 달리 **프리셋 파일을 쓰지 않습니다.** 항목 목록은 노드가 직접 들고 있고 워크플로에 함께 저장됩니다. 노드마다 다른 체크리스트를 두기 위해서입니다.

---

## 화면 구성

```
┌ 체크리스트 (1/2)      [LoRA] ┐   ← 머리글: 프롬프트 토글 + 로라 일괄 토글
│ ( ○ 흰 배경       L2 L1 ⚙ )  │   ← 켜짐(노랑) / 꺼짐(회색)
│ ( ● [ 밤            ] L2 ⚙ )  │   ← 설정을 열면 제목이 이 자리에서 바로 고쳐진다
│ ┌──────────────────────────┐ │
│ │ [ 프롬프트              ]│ │   ← 고정 높이 + 스크롤
│ │ [ 여러 줄 입력        ▲▼]│ │
│ │ ( ● bed/wooden ◀0.90▶ ✕ )│ │
│ │ ( ● night/dark ◀0.90▶ ✕ )│ │
│ │ [＋ 로라 추가][🗑 항목 삭제]│ │
│ └──────────────────────────┘ │
│ [        ＋ 항목 추가       ] │
└──────────────────────────────┘
```

| 요소 | 동작 |
|---|---|
| 머리글 **토글** | 이 노드의 프롬프트를 넣을지 여부. 끄면 전체가 회색이 됩니다. |
| 머리글 `(2/5)` | 켜진 항목 수 / 전체 항목 수 |
| 머리글 `LoRA` 배지 | 끄면 로라를 하나도 적용하지 않습니다. 로라가 달린 항목이 없으면 보이지 않습니다. |
| 항목 줄 **토글·제목** | 아무 데나 누르면 켜고 꺼집니다. |
| 항목 줄 `⚙` | 그 항목의 설정 패널을 펼칩니다. 다시 누르면 닫힙니다. |
| 항목 줄 `L2 L1` | 그 항목의 로라 개수. **켜진 것은 노란색, 꺼진 것은 회색**으로 나눠 보여줍니다. 3개 중 2개가 켜져 있으면 `L2 L1` 입니다. 한쪽이 0개면 그쪽은 나오지 않고, 로라가 아예 없으면 둘 다 없습니다. |
| 설정 `제목` | 설정을 열면 **항목 줄의 제목 자리가 그대로 입력 상자로 바뀝니다.** 목록에서 구분하기 위한 이름일 뿐 **출력에는 나가지 않습니다.** |
| 설정 `프롬프트` | 여러 줄 입력. 이 항목을 켰을 때 **실제로 나가는 텍스트**입니다. 높이는 `PROMPT_HEIGHT`(96px) 고정이고, 내용이 넘치면 칸 안에서 스크롤됩니다. |
| 설정 로라 줄 | 토글 · 이름(누르면 교체) · `◀ 0.90 ▶`(강도) · `✕`(삭제) |
| `＋ 로라 추가` | 목록에서 고른 뒤에만 줄이 추가됩니다. |
| `🗑 항목 삭제` | 확인 후 그 항목을 지웁니다. |
| `＋ 항목 추가` | 빈 항목을 만들고 바로 설정 패널을 펼칩니다. |

**기본은 빈 상태입니다.** 항목을 하나도 주지 않습니다. `＋ 항목 추가` 로 직접 만듭니다.

**제목은 목록에서 구분하기 위한 이름일 뿐입니다.** 출력 프롬프트에는 들어가지 않고, 아래 프롬프트 칸의 내용만 합쳐집니다.

제목을 비워두면 목록에는 프롬프트 앞부분이 대신 보입니다. 둘 다 비면 `(빈 항목)` 으로 보이고, **저장할 때 사라집니다.**

## 입출력

### 입력

| 이름 | 타입 | 필수 | 설명 |
|---|---|---|---|
| `items_data` | STRING | O | 항목 목록 JSON (UI가 관리, 화면에서 숨김) |
| `delimiter` | STRING | O | 항목 사이에 넣을 문자. 기본 `", "` (화면에서 숨김) |
| `prompt_enabled` | BOOLEAN | O | 프롬프트 사용 여부 (화면에서 숨김) |
| `loras_enabled` | BOOLEAN | O | 로라 사용 여부 (화면에서 숨김) |
| `model` | MODEL | — | 없어도 동작. 없으면 로라를 건너뜁니다 |
| `clip` | CLIP | — | 위와 같음 |
| `prompt_in` | STRING | — | 앞 노드의 프롬프트. 연결하면 맨 앞에 붙습니다 |

### 출력

| 이름 | 타입 | 설명 |
|---|---|---|
| `MODEL` | MODEL | 로라가 적용된 모델 (입력이 없으면 `None`) |
| `CLIP` | CLIP | 로라가 적용된 클립 |
| `prompt` | STRING | `prompt_in` + 켜진 항목들의 프롬프트를 `delimiter` 로 이은 것 |

---

## 프롬프트 조합

켜진 항목만 **목록에 놓인 순서대로** 이어집니다. 프롬프트가 빈 항목은 건너뜁니다.

```
prompt_in           "1girl, masterpiece"
☑ 흰 배경           "solid white background"
☐ 오른쪽 햇빛       (꺼짐 → 빠짐)
☑ 밤                "night, dark light"

출력  1girl, masterpiece, solid white background, night, dark light
```

`delimiter` 를 바꾸면 이음새가 달라집니다. 화면에서는 숨겨져 있고 노드 속성 패널에서 고칩니다.

---

## 두 개의 바이패스

프롬프트와 로라를 **각각 독립적으로** 끌 수 있습니다. [FLALoraTheme](FLALoraTheme.md) 과 같은 방식입니다.

| 프롬프트 | 로라 | 적용 로라 | 출력 프롬프트 |
|---|---|---|---|
| 켬 | 켬 | 켜진 항목의 로라 | `base, a, b` |
| 켬 | 끔 | 0개 | `base, a, b` |
| 끔 | 켬 | 켜진 항목의 로라 | `base` |
| 끔 | 끔 | 0개 | `base` |

끄더라도 **각 항목과 각 로라의 on/off 상태는 그대로 남습니다.**

### 로라 중복

여러 항목이 같은 로라를 가리키면 **처음 것만 적용합니다.** 두 번 얹으면 강도가 겹쳐서 의도와 달라지기 때문입니다. `checklist.active_loras()` 가 처리합니다.

---

## 데이터 저장

항목은 `items_data` 위젯에 JSON 문자열로 들어가고, **워크플로 `.json` 에 함께 저장**됩니다.

```json
[
  {
    "title": "흰 배경",
    "prompt": "solid white background",
    "loras": [
      { "path": "style\\whitebg.safetensors", "strength": 0.9, "enabled": true }
    ],
    "enabled": true
  }
]
```

| | |
|---|---|
| 저장 위치 | 워크플로 `.json` (노드별) |
| 공유 범위 | 그 노드 하나. 다른 노드·워크플로와 공유하지 않습니다 |
| 다른 워크플로로 옮기려면 | 노드를 복사해서 붙여넣습니다 |

프리셋 파일을 쓰지 않으므로 **API 라우트가 없습니다.** 로라 목록만 기존 `/fla/loras` 를 함께 씁니다.

## 주의할 점

**위젯 순서** — JS로 추가한 위젯은 전부 `serialize = false` 입니다. 파이썬 위젯 4개(`items_data`, `delimiter`, `prompt_enabled`, `loras_enabled`)는 순서를 바꾸지 않고 그대로 두므로 `flaOriginalOrder` 같은 되돌리기가 필요 없습니다.

**프롬프트 칸은 항목마다 따로** — `itemPromptWidget()` 이 항목별로 `ComfyWidgets.STRING` 위젯을 하나씩 만들어 캐시합니다(`node.flaPromptWidgets`). 하나를 돌려쓰면 위젯이 어느 항목을 가리키는지가 열고 닫는 순서에 따라 달라져, 닫은 뒤 뒤늦게 들어온 입력이 엉뚱한 항목에 쓰입니다. 펼쳐진 항목의 것만 보이고 나머지는 감춥니다. 항목을 지우면 `dropPromptWidget()` 이 DOM 까지 정리합니다.

**제목 칸은 `rebuild` 마다 새로 만듭니다.** 겹쳐 그리는 대상(항목 줄)도 매번 새로 만들어지므로 클로저로 곧장 묶는 편이 단순하고, 실제로 문제없이 동작합니다.

이 위젯들은 **JS 가 만든 것이므로 `serialize = false`** 입니다. 반대로 파이썬 위젯(`items_data` 등)에는 절대 붙이면 안 됩니다. 저장 슬롯이 사라져 뒤쪽 값이 밀리고 복사·붙여넣기 때 내용이 초기화됩니다.

**복원 순서** — `onConfigure` 가 `onNodeCreated` 보다 먼저 실행될 수 있습니다. 그래서 `onNodeCreated` 는 `flaItems` 를 `[]` 로 두지 않고 `readItems()` 로 위젯에 남아 있는 값을 먼저 읽습니다. 이 처리를 빼면 `rebuild` → `syncHidden` 이 빈 값을 덮어써서 **새로고침할 때마다 항목이 사라집니다.**

**정본은 `items_data`** — 복원할 때 파이썬 위젯 값을 먼저 읽고, 없을 때만 `o.flaItems` 를 씁니다. 두 곳에 두는 이유는 예전 워크플로 호환입니다.

**입력 칸** — `addWidget("textarea", ...)` 는 **Node 2.0 전용**이라 기존 캔버스에서는 `Textarea: Node 2.0 전용` 자리표시만 나옵니다. 그래서 `makeInputWidget()` 이 진짜 `<input>`/`<textarea>` 를 직접 얹고 `draw` 때마다 캔버스 좌표·확대율에 맞춰 위치를 옮깁니다. 패널을 닫거나 노드를 지우면 `flaElement` 를 찾아 DOM에서 제거합니다.

**프롬프트 높이는 고정** — `PROMPT_HEIGHT` 상수(96px)를 씁니다. `height` 만 주면 테마 CSS 기본값에 밀릴 수 있어 `min-height`·`max-height` 를 함께 못박습니다. 남는 공간을 흡수하게 만들면 `노드 높이 → 프롬프트 높이 → 위젯 높이 합 → 노드 높이` 로 서로를 참조해서 설정을 열 때마다 칸이 계속 늘어납니다. 내용이 넘치면 `overflow-y: auto` 로 칸 안에서 스크롤합니다.

**입력칸이 튀어 보이지 않게** — DOM 입력칸은 세 가지로 잔상을 막습니다. ① `display` 대신 `visibility` 로 감춥니다(자리와 크기를 유지한 채 숨기므로 나타날 때 움직이지 않습니다). ② **자리를 먼저 옮기고 그다음 크기를 줍니다.** 순서가 반대면 옛 자리에서 커졌다가 이동하므로 "위에서 크게 나타났다가 제자리로 가며 작아지는" 것처럼 보입니다. 좌표·크기를 모두 대입한 **뒤에** `visible` 로 바꿉니다. 만들 때는 화면 밖(`-9999px`)에 크기 `0` 으로 둬서 첫 프레임에 깜빡이지 않게 하고, `textarea` 의 `rows` 기본값이 최소 높이로 잡히지 않도록 `rows=1` 과 `min/max-height: 0` 을 함께 둡니다. ③ `rebuild()` 도중에는 `flaBuilding` 플래그로 계속 숨겨둡니다. 이때는 노드 크기와 줄 위치가 아직 확정되지 않아서, 자리를 잡으면 엉뚱한 곳에 커진 채 나타났다가 제자리로 돌아옵니다.

**제목 칸의 위치** — 제목 입력은 줄을 따로 만들지 않고 항목 줄 위에 **겹쳐** 그립니다(`overlay`). 항목 줄이 `draw` 때 남겨둔 `flaTitleBox` 좌표를 따라가고, `computeSize` 는 `0` 을 돌려줘 높이를 차지하지 않습니다. 그래서 패널이 한 덩어리로 보입니다.

**빈 항목** — 제목·프롬프트·로라가 모두 비면 `checklist.normalize_item()` 이 버립니다. 화면에서 만든 직후에는 남아 있다가 다시 열면 사라지므로, 새 항목은 만들자마자 내용을 채웁니다.
