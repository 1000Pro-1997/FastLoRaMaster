# 오류 진단 기록

## 커스텀 위젯이 보이지만 안 눌릴 때

다음 항목을 순서대로 확인한다.

- 화면에 그린 영역과 실제 클릭 판정 영역이 같은 좌표와 크기를 사용하는가?
- `draw()`에 전달되는 폭과 `node.size[0]`을 섞어서 사용하지 않았는가?
- 오른쪽 속성 패널이 공유 위젯의 `widget.width`를 덮어쓰지 않았는가?
- `computeSize()`가 반환한 높이와 실제로 그린 높이가 일치하는가?
- 높이 0인 테두리·오버레이 위젯이 클릭을 먼저 가로채지 않는가?
- 위젯 재생성 후 `canvas.node_widget`이 제거된 옛 위젯을 계속 참조하지 않는가?
- `pointerdown` 도중 위젯 목록을 즉시 교체하지 않았는가?
- `widget.mouse()`의 예외 때문에 포인터 캡처가 남지 않았는가?
- 클릭 동작은 `pointerup`에서 한 번만 실행되는가?

## LoRA 삭제 버튼이 안 눌렸던 사례

### 증상

- LoRA 가중치 증가 버튼은 동작한다.
- 바로 오른쪽의 삭제 버튼은 보이지만 눌리지 않는다.
- 위젯을 다시 만들면 폭이 잠시 정상으로 돌아온다.
- 다시 그린 뒤 노드 내부 UI 폭이 작아지기도 한다.

### 원인

중앙 캔버스 노드와 오른쪽 속성 패널이 같은 위젯 객체를 사용했다. 속성 패널은 자기 폭에 맞추기 위해 `widget.width`를 덮어썼고, ComfyUI 캔버스는 이후 그 값으로 위젯 폭과 클릭 영역을 계산했다.

따라서 중앙 노드의 오른쪽 끝에 보이는 삭제 버튼이 실제 클릭 가능 영역 밖으로 밀렸다. 증가 버튼은 삭제 버튼보다 왼쪽에 있어 좁아진 영역 안에 남았기 때문에 동작했다.

### 수정 원칙

- 속성 패널이 저장한 폭이 캔버스 위젯 상태에 남지 않도록 한다.
- 캔버스의 그리기 폭과 클릭 판정 폭은 모두 노드 전체 폭을 사용한다.
- 속성 패널은 `draw()` 호출 시 직접 전달하는 패널 폭만 사용한다.
- LoRA 테마와 체크리스트의 공용 구현은 `web/fla_lora_ui.js`에서 함께 수정한다.

현재 공용 LoRA 위젯은 `ignoreStoredWidth()`로 외부에서 저장하려는 `widget.width`를 무시한다. 캔버스에서는 `widget.width`가 없는 것처럼 노드 폭을 사용하고, 속성 패널은 자신의 `draw()` 인자로 받은 폭을 사용할 수 있다.
